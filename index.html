THE METHOD // POST 03

Run it yourself.

A 30B model on a 4 GB laptop GPU. The exact command from the take, the machine it ran on, and what it measured. If your laptop is close to this one, you can check every number.

llama-server -m Qwen3-30B-A3B-Instruct-2507-UD-Q3_K_XL.gguf -ngl 99 --n-cpu-moe 48 -t 12 -fa on -c 8192

The trick is llama.cpp's own option, --n-cpu-moe: it keeps the experts' weights in system RAM and the rest on the GPU. We measured it on this laptop; we did not invent it.

No NVIDIA card? Vulkan.

The same file on an AMD laptop's integrated graphics - half a gigabyte of its own memory. Every run first failed with 'radv/amdgpu: Not enough memory for command submission' - even with all experts on the CPU. llama.cpp pins the CPU-side weights as Vulkan host buffers, and on an integrated GPU that pinned ~12 GB overflows the GPU's shared-memory window. The fix: --no-host 1 (keep the CPU-side weights in plain RAM) and -lm none. With those, the same 30B file runs on a laptop iGPU that has half a gigabyte of its own memory.

llama-bench -m Qwen3-30B-A3B-Instruct-2507-UD-Q3_K_XL.gguf -ngl 99 -fa 1 -t 10 -lm none --no-host 1 --n-cpu-moe 12
