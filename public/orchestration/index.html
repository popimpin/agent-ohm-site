STEP 1 OF 6What happened?
Step 1 · What happened?

A real run broke on camera. Here's what happened next.

Getting things right isn't "nothing ever fails". It's what happens next: the failure is caught, the damage is put back, the cause is found and guarded, and the clean run follows. Here is one, start to finish, from the recordings.

The agent wrote this run and started it. Its own cursor drives the real design tool and the real team calendar: open the calendar, then book five posts into it, one form at a time. Nobody is at the keyboard. 116 seconds in, it stops.

TAKE 1435 // 116.1 S // FAILED

A "take" is one recorded run. These are the browser's own frames, not a screen recorder. The first post is booked on camera; the click for the second lands, and nothing opens.

Step 2 · Why did it fail?

An invisible notice was in the way.

The "Booked" notice from the first booking had faded to invisible, but it was still there and still clickable, sitting on the calendar's bottom row. The agent's click on the 28th hit the notice, not the day.

103.6 s → 106.8 s, frame by frame.

Why no practice run caught it: every rehearsal pressed Cancel, which shows no notice. Only the real booking could hit it.

Step 3 · What did it break?

Four real bookings were left cancelled.

The form never opened, so the step waiting for it timed out. Worse: the run had already cleared the old bookings to make room, so the calendar was left with four posts cancelled.

That's the price of real clicks in a real app. A run that only clicks a mock-up can't fail this way, and can't prove anything either.

Step 4 · What came first?

Put things back first. Fix the code second.

The four bookings were put back first, through the calendar's own screens, with the same titles and times. Fix the damage before you fix the code.

Step 5 · Will it happen again?

One cause, one guard.

  1. The notice lets clicks through now.It had no rule letting clicks pass under it. Now it does, so a faded notice can't catch a click.
  2. Every run puts the calendar back.Whatever happens, the run restores the bookings it touched before it ends.
  3. A failure is reported as a failure.Take 1435 had ended by saying "success". Now a run that fails says so.
Step 6 · Did it work after?

Eight minutes later, it ran clean.

Take 1443 ran start to finish in 185 seconds. That take became the post.

TAKE 1435 // FAILED AT 116 S
TAKE 1443 // CLEAN, 185 S

Why show the failure at all? Because a demo with no failures in it is either very short or edited.

The speed bumps stay in. They're the part you can check.
